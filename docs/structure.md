# Project Structure

## 현재 상태

기획·설계 문서는 대부분 완료(기획안/기능 명세서/IA/DB ERD/API 문서)됐고, 실제 소스 코드는 아직 없다. 저장소 최상위에 문서만 존재하는 상태 (`.kiro/` 서브디렉토리 없이 이 steering 문서들도 루트에 위치).

```
26s-w1-c3-02/
├── README.md          # 팀/기획안/기능명세서/IA/DB스키마/API문서/배포/회고 — 전체 진행 상황 허브
├── api-spec.md         # API 상세 스펙: 공통 규약(인증·페이지네이션·에러 포맷), ENUM 정의, 엔드포인트별 요청/응답 예시
├── product.md          # 이 문서와 함께 보는 steering 문서: 제품 개요
├── structure.md         # 이 문서: 저장소/문서 구조
├── tech.md              # steering 문서: 기술 스택
└── screenshot/          # IA 와이어프레임, 화면 목업, DB ERD(db_shcema.png) 이미지
```

## 문서 간 관계

- **README.md**가 진행 상황을 보여주는 메인 허브. "API 문서" 섹션은 엔드포인트 목록을 요약 표로만 담고, 상세 스펙(ENUM, 객체 스키마, 에러코드 등)은 `api-spec.md`로 링크한다.
- **api-spec.md**가 API의 단일 진실 공급원(source of truth). 프론트/백엔드 구현 시 이 문서의 요청/응답 스키마를 기준으로 삼는다.
- README.md는 프로젝트 진행 단계에 맞춰 아래 섹션을 순서대로 채워나가는 구조:
  1. 팀원
  2. 기획안 (주제/목적/핵심 기능/예상 사용자/역할)
  3. 기능 명세서 (필수/선택 기능)
  4. IA 및 화면 설계서 (와이어프레임) — 완료
  5. DB 스키마 (ERD) — 완료 (`screenshot/db_shcema.png`)
  6. API 문서 — 완료 (요약은 README, 상세는 `api-spec.md`)
  7. 배포 결과물 — 미작성 (서비스 URL/실행 방법 대기)
  8. 회고 문서 (KPT) — 미작성

기능이나 설계가 바뀌면 코드보다 먼저 이 문서들을 갱신하는 것을 원칙으로 한다.

## 향후 구조 (예정)

기술 스택은 확정(`tech.md` 참고: React + Django + MySQL). 소스 코드가 추가되면 프론트엔드/백엔드 디렉토리 분리(예: `frontend/`, `backend/`) 여부와 모노레포 구성을 이 문서에 반영하고, 실제 폴더 구조와 네이밍 컨벤션으로 이 섹션을 대체할 것.
